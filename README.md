# 第1部：プロダクト企画書（外部設計）

## 1. プロダクト概要

テキトリップは、現在地を基準にランダム性を持たせた行き先候補を提示するWebアプリケーションである。
ユーザーの「どこか行きたいが決められない」という状態を解消することを目的とする。

主な対象カテゴリ： - フード＆ドリンク - ショッピング -
アウトドア＆レクリエーション - 宿泊

------------------------------------------------------------------------

## 2. ユーザー体験

1.  距離モードを選択
2.  カテゴリを選択
3.  「提案！」を押す
4.  5件の候補がカード形式で表示
5.  「もう一回！」で完全再抽選

特徴： - 条件は固定したまま中身だけシャッフル可能 -
海上検索を避けることで不自然な結果を抑制 -
ランダム性と実用性のバランスを重視

------------------------------------------------------------------------

## 3. 距離モード

  モード     表示名        距離リング   検索半径
  ---------- ------------- ------------ ----------
  justnow    ここらへん    0.5km        0.5km
  near       今から行く    15km         2km
  mid        1日かけ行く   50km         5km
  minitrip   1泊まで       100km        10km
  far        旅行で行く    200〜800km   50km

リング距離は ±20% ランダム化。

------------------------------------------------------------------------

## 4. 技術構成

-   Google Maps JavaScript API
-   Places API (New)
-   Maps Static API（海上判定用）
-   GitHub Pages
-   PWA対応

# 第2部：詳細設計（エンジニア向け）

## 1. サーチアルゴリズム

### 1.1 バッチ制御

-   最大50バッチ
-   成功バッチ最低3回
-   成功条件：5件以上ヒット
-   失敗バッチはカウントしない

終了条件： 成功バッチ \>= 3 かつ 候補数 \>= 表示件数 × 3

------------------------------------------------------------------------

## 2. 検索地点生成

### 2.1 距離計算

ringKm_actual = random(ringMinKm, ringMaxKm) × random(0.8, 1.2)

### 2.2 方角制御

使用角度例： 0°,150°,300°,60°,210°,120°,30°,240°

------------------------------------------------------------------------

## 3. 海上判定

1.  Static Maps API で 200x200 画像取得
2.  青系ピクセル割合を判定
3.  閾値超過なら海上扱い
4.  Nearby Search を実行しない

------------------------------------------------------------------------

## 4. 候補管理

-   place.id をキーに重複排除
-   ランダムに5件抽出

------------------------------------------------------------------------

## 5. 表示仕様

表示項目： - 写真（Nearby優先、なければPhotoAPI） - 名称 - カテゴリ名 -
評価 - 住所 - Google Mapsリンク

リンク形式：
https://www.google.com/maps/search/?api=1&query=NAME&query_place_id=ID

------------------------------------------------------------------------

## 6. キャッシュ対策

app.js?v=YYYYMMDDhhmm を自動付加

------------------------------------------------------------------------

## 7. APIコスト最適化

-   海上除外
-   最低成功バッチ制御
-   PhotoAPI最小使用
-   重複除外
